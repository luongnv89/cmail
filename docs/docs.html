Install

curl -fsSL https://raw.githubusercontent.com/luongnv89/cmail/main/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"
cmail --version

To install a clone you reviewed instead, with no downloads:

git clone https://github.com/luongnv89/cmail
cd cmail
bash install.sh --local
WhatWhereOverride at install
Launcher~/.local/bin/cmailCMAIL_BIN_DIR
Runtime~/.local/share/cmail/CMAIL_DATA_DIR
Config~/.config/cmail/.envCMAIL_CONFIG_DIR
  • The one-line command and plain bash install.sh download the pinned v0.2.0 runtime from GitHub. --local installs the checkout you cloned, with no downloads.
  • The installer says whether ~/.local/bin is on your PATH and prints the export PATH line to add to your shell profile if it is not.
  • Needs Bash 3.2+, curl and jq. No sudo. Installing never runs setup or edits your shell profile.
  • To update, run the installer again (for a clone, pull it first). Your config is kept.

example
$ cmail list
Addresses on example.com (2):
  contact@example.com -> owner@example.net (verified)  [disabled]
  hello@example.com   -> owner@example.net (verified)
Catch-all (any other address): disabled -> drop

$ cmail doctor --offline
PASS  bash available
PASS  curl available
PASS  jq available

Destinations are marked verified, unverified (click the Cloudflare link) or unregistered.

To move an existing address to a new inbox, run cmail forward hello --destination new@example.org in a terminal. The address and its rule stay; only the destination changes. If Cloudflare has not verified the new inbox, nothing changes: cmail offers to send the verification email, and you rerun the command after clicking the link. DEST_EMAIL is updated only when every configured address then forwards to the new inbox.

Configuration

Settings live in one private file (mode 600). cmail setup fills it for you; set values ahead of time if you prefer:

cmail config set DOMAIN example.com
cmail config set DEST_EMAIL you@gmail.com
cmail config set ADDRESSES hello,contact
cmail config set CLOUDFLARE_API_TOKEN --stdin < /path/to/private/token
cmail config check
KeyMeaning
DOMAINYour domain, e.g. example.com
DEST_EMAILInbox that receives the mail
ADDRESSESComma-separated names: hello,contact
CLOUDFLARE_API_TOKENScoped API token (secret; set via --stdin or setup’s hidden prompt)
REGISTRARmanual (default) or godaddy
CF_ACCOUNT_IDOptional. Pick a Cloudflare account when you have several
CF_ZONE_IDSaved by setup. No need to set
GDDY_ENV, GDDY_PATGoDaddy mode only: environment and optional token
DRY_RUN1 = same as setup --dry-run

Precedence: command option → environment variable → config file → default. Pick another file with --config PATH or CMAIL_CONFIG.

Values are plain literals. Shell commands and $(…) expansions are rejected. Secrets never go on the command line.

Registrar modes

manual · default

Any registrar. cmail prints the Cloudflare nameservers; you set them at your registrar while cmail waits. It never changes delegation and never buys a domain.

godaddy · opt-in

Uses the gddy CLI to pick a GoDaddy domain and switch nameservers after you confirm. The only mode that can offer a purchase, which needs the domain typed at a terminal.

cmail setup --domain example.com      # any registrar
cmail setup --registrar godaddy       # opt in once
cmail config set REGISTRAR godaddy    # opt in permanently

Preview & JSON

setup --dry-run previews the whole workflow: no provider changes, purchases, config writes or browser launches. It exits 0 even with blockers, so read data.blockers.

cmail setup --dry-run --format json
cmail status --format json | jq '.data.rules'
cmail doctor --offline --format json

JSON is available for status, list, doctor, config show/check and previews:

{"schema_version":1,"command":"status","data":{"zone":{},"routing":{},"destinations":[],"rules":[]}}

Setup and send-as need a real terminal. In scripts, use --dry-run.

Global options

-c, --config PATHUse a specific config file
-f, --format text|jsonReport format
-v, --verbose / -q, --quietMore (redacted) detail / less progress
--no-colorPlain output (also NO_COLOR)
--no-browserPrint links instead of opening them
--timeout SECONDSHTTP timeout, default 30
setup --wait-timeout SECONDSEach activation/verification wait, default 1200
-h, --help · -V, --versionHelp and version

Results go to stdout; progress, prompts and errors to stderr.

Shell completions

# bash
cmail completion bash > ~/.cmail-completion.bash
echo 'source ~/.cmail-completion.bash' >> ~/.bashrc

# zsh (put fpath before compinit in .zshrc)
mkdir -p ~/.zfunc && cmail completion zsh > ~/.zfunc/_cmail

# fish
cmail completion fish > ~/.config/fish/completions/cmail.fish
