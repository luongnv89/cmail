  1. 1
    You2 min

    Check you have everything

    • A domain you own, at any registrar.
    • A free Cloudflare account.
    • The inbox that should receive the mail (any provider).
    • A second mailbox to send a test from.
    • macOS or Linux with bash, curl, jq and git.

    Already use this domain for a website or email? Note its DNS records now. You will copy them into Cloudflare in step 5.

    Done when: you can log in to your registrar, Cloudflare and both mailboxes.

  2. 2
    You2 min

    Install cmail

    1. Clone the repository.
    2. Run the installer. It copies cmail to ~/.local/bin. No sudo needed.
    3. Create your private config file and choose your addresses (default: hello).
    git clone https://github.com/luongnv89/cmail
cd cmail
bash install.sh --local
export PATH="$HOME/.local/bin:$PATH"
cmail --version
cmail config init
cmail config set ADDRESSES hello,contact

    Add the export PATH line to your shell profile to keep it. Config lives in ~/.config/cmail/.env (mode 600).

    Done when: cmail --version prints cmail 0.2.0.

    ~/cmail
    $ cmail --version
cmail 0.2.0
$ cmail config init
Created private configuration: ~/.config/cmail/.env
Next: cmail setup
$ cmail config set ADDRESSES hello,contact
  3. 3
    You3 min

    Create a Cloudflare API token

    1. Open My Profile → API Tokens → Create Token → Custom token → Get started.
    2. Add the five permissions shown on the right.
    3. Zone Resources: Include → All zones from an account → your account.
      Account Resources: Include → the account that owns your domain.
    4. Create the token and copy it. You paste it in the next step.

    Never paste the token into chat, a web page or a screenshot. cmail asks for it with hidden input.

    Done when: the token is created with all five permissions and copied somewhere private.

  4. 4
    cmailYou2 min + waits

    Run cmail setup

    cmail setup

    Answer two questions, then paste your token:

    1. Receiving inbox, e.g. you@gmail.com
    2. Your domain, e.g. example.com

    cmail then creates the Cloudflare zone, enables Email Routing and adds a forwarding rule per address. It stops only when it needs you (steps 5 and 6).

    Want a preview first?

    cmail setup --dry-run shows the full plan and any blockers. It changes nothing. It needs the token saved in your config first.

    Done when: setup is running past the token step. Keep the terminal open.

  5. 5
    YouWait5 min + DNS time

    Point your domain at Cloudflare

    Skip this if setup says zone already active on Cloudflare. Otherwise, at your registrar:

    1. Copy DNS records you still need (website, MX, TXT) into Cloudflare → your domain → DNS.
    2. Turn off DNSSEC (remove DS records). Re-enable it from Cloudflare later.
    3. Replace all nameservers with the two that cmail printed. Save.

    cmail checks every 20 seconds for up to 20 minutes. Propagation can take up to 24–48 hours. If the wait ends first, just run cmail setup again.

    You1 min

    Click the verification email

    1. Open your receiving inbox. Check Spam too.
    2. Open the email from Cloudflare and click Verify email address.
    3. Go back to the terminal. cmail notices within 15 seconds and finishes.

    No email? In Cloudflare → Email Routing → Destination addresses, resend it. Then rerun cmail setup.

    Done when: the terminal shows Receiving is set up.

  7. 7
    You2 min

    Send yourself a test

    1. From a different mailbox, email hello@your-domain.
    2. Check it arrives in your receiving inbox (and Spam).
    3. Repeat for each address. cmail list shows them all.

    Sending from the receiving inbox itself can be silently dropped by some providers, so it is not proof.

    Done when: a test message arrives for every address.

    cmail list
    $ cmail list
Addresses on example.com (2):
  contact@example.com -> you@gmail.com (verified)
  hello@example.com   -> you@gmail.com (verified)
Catch-all (any other address): disabled -> drop
  8. 8
    OptionalYou5 min

    Optional: send from your address

    Sending is optional. Skip this if you only need to receive. It needs a Gmail account.

    Google has announced it will remove third-party “Send as” starting January 2027. Check Google’s help first.

    cmail send-as
    1. Create a Google App Password (needs 2-Step Verification).
    2. Gmail → Settings → Accounts and Import → Send mail as → Add another email address.
    3. Enter the SMTP settings on the right. Confirm with the code Gmail emails to your new address.

    App Passwords may be unavailable on work/school accounts or with Advanced Protection. Don’t disable security to work around it.

    Done when: a message sent “from” your address reaches another mailbox, or you skipped this step.

Stuck?

Setup stopped

Read the Setup stopped at: line, fix that step, then rerun cmail setup. Finished steps are skipped.

Check the state

cmail status shows zone, routing, destination and rules. cmail doctor checks tools, config and token.

Token errors

A 403 names the missing permission. Edit the token in Cloudflare, add it, and rerun setup.

More in the CLI docs and the troubleshooting reference. Using GoDaddy? cmail setup --registrar godaddy can switch nameservers for you.

Checkmarks are your own record. They never change provider settings.
